# 多文档产出结构

对话结束时，根据收集的信息生成以下文档：

## 00-执行摘要.md

**读者**：领导/决策者  
**目的**：1分钟看完，快速决策  
**长度**：1页纸（500字以内）

**结构**：
```markdown
# [项目名] · 执行摘要

## 一句话
用AI将会议纪要覆盖率从<10%提升至20%，月均节省3000小时。

## 痛点
全集团月均3万场会议，90%以上"开完就忘"，跨部门待办靠自觉。

## 方案
云图梭会议结束后自动生成结构化纪要 + 同步待办 + 推送摘要。

## ROI
- 投入：15万（3个月）
- 产出：年化节省50万人力成本 + 待办闭环率从<20%→60%
- 杠杆：1:12

## 申请
申请15万预算，3人兼职团队，3个月交付MVP。
```

## 01-立项书.md

**读者**：评委/审批人  
**目的**：按模板正式提交  
**依据**：DT 7项模板 / 千丁 8项模板

**结构**（DT 7项）：
1. 项目名称
2. 组队人员（姓名+部门+专职/兼职）
3. 申请金额（拆分明细）
4. 预期业务价值（段永平三问）
5. 成功标尺（目标值+统计口径+数据来源）
6. 项目计划（里程碑）
7. 涉及的AI相关技术

**风格**：正式、完整、无checkbox

**读者**：技术评委/架构师  
**目的**：技术可行性评估  

**结构**：
```markdown
# [项目名] · 技术方案

## 架构图
[文字描述或mermaid]

## 技术选型
| 模块 | 选型 | 理由 | 备选 |
|------|------|------|------|
| ASR | 阿里云语音 | 中文支持好 | 讯飞 |
| LLM | GPT-4o | 长文本强 | Claude |

## 数据流
1. 会议结束触发
2. ASR转写 → 文本
3. GPT提取 → 结构化数据
4. 写入待办系统 + 推送群聊

## 数据飞轮
- 收集：用户修改数据
- 回流：优化Prompt/微调模型
- 评估：准确率、采纳率

## Eval体系
- 离线：50场黄金标准数据集
- 在线：采纳率、修改率
```

## 生成规则

1. **信息复用**：同一信息只在最合适的文档出现，其他文档引用
   - 例：成功标尺详细定义只在01-立项书，02-项目计划只引用目标值

2. **读者优先**：每个文档按读者的需求组织，不是按信息类型组织
   - 评委关心"为什么做"→01-立项书重业务价值
   - 团队关心"怎么做"→02-项目计划重任务拆解

3. **可省略**：不做Step 5则没有04-评审记录

4. **一致性**：同一数字在各文档中必须一致（如预算15万）
