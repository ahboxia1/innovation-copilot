# 好的立项书示例（虚构示范）

> 以下是一个虚构的示范立项书，展示copilot引导用户应达到的质量标准。
> 场景设定：某物业公司IT部门内部员工提出，属于DT AI季度探索项目。

---

# 智能巡检报告生成助手 · 立项书

## 项目概述

**定位**：用AI视觉模型替代物业项目巡检报告的人工编写环节。
**核心目标**：将单次巡检报告编写时间从25分钟缩短至5分钟，同时提升缺陷描述的标准化程度。

## 项目背景与痛点

**业务现状**：
- 覆盖**86个**物业项目，月均巡检**430+次**
- 每次巡检产生**20-40张**现场照片，需要人工逐张描述问题、分类、定级
- 单次巡检报告平均编写时间**25分钟**，巡检员**40%工时**消耗在写报告而非现场检查

**痛点量化**：

| 指标 | 数值 | 来源 |
|------|------|------|
| 月均巡检次数 | 430次 | 巡检系统后台统计（2025Q4均值） |
| 单次报告编写时间 | 25分钟 | 抽样50次巡检计时均值 |
| 巡检员报告编写工时占比 | 40% | 工时系统分类统计 |
| 报告退回重写率 | 18% | OA审批流统计 |
| 退回原因Top3 | 描述不清(52%)、分类错误(28%)、漏拍(20%) | 人工归因分析 |

**现有方案及不足**：
- 当前方式：巡检员手机拍照 → 回办公室后逐张看图写文字描述 → 提交OA审批
- 主要不足：描述标准不统一（同一个"墙面渗水"有15种写法）、耗时过长、退回率高

## 核心方案

**技术架构**：

```
手机拍照 → 图片上传 → VLM多模态模型（视觉理解+缺陷描述生成）
                              ↓
                    结构化输出：缺陷类型 / 位置 / 严重程度 / 修复建议
                              ↓
                    自动生成巡检报告 → 推送OA审批
```

**技术选型**：

| 技术组件 | 选型 | 解决的问题 |
|----------|------|-----------|
| 视觉理解 | Claude 3.5 Sonnet (多模态) | 识别照片中的缺陷类型、位置、严重程度 |
| 描述生成 | Few-shot Prompting（8个示例） | 生成标准化缺陷描述，统一用语 |
| 报告组装 | 模板引擎（本地Python脚本） | 按公司巡检报告模板自动填充 |

**与现有方案对比**：

| 维度 | 人工编写 | AI辅助生成 |
|------|---------|-----------|
| 单次耗时 | 25分钟 | 预估5分钟（AI生成+人工复核） |
| 描述标准化 | 低（同一问题15种写法） | 高（Few-shot约束输出格式） |
| 退回率 | 18% | 目标<=8% |

**已有验证成果**：

随机抽取**30份**历史巡检照片（覆盖5个常见缺陷类型），用Claude 3.5 Sonnet生成描述：

| 指标 | 结果 |
|------|------|
| 缺陷类型识别准确率 | **91%**（27/30正确分类） |
| 描述可用率 | **87%**（26/30无需修改直接可用） |
| 平均生成时间 | **3.2秒/张** |

> 验证方式：2名资深巡检主管盲评，与人工编写的报告对比。

## 经费使用（2.4万）

| 用途 | 金额 | 计算方式 |
|------|------|---------|
| Claude API调用 | 1.2万 | 约7200次调用/月 x 3月，单次成本约0.55元（基于Sonnet定价） |
| Claude Max订阅 | 0.6万 | $100/月 x 3月 x 2人，用于prompt调试和复杂场景测试 |
| 测试数据标注 | 0.6万 | 外包标注500张巡检照片的缺陷类型+严重程度（1.2元/张） |

## 涉及的AI技术

| 技术 | 一句话说明解决什么问题 |
|------|---------------------|
| 多模态大模型（VLM） | 理解巡检照片中的缺陷内容，替代人工看图写描述 |
| Few-shot Prompting | 用8个标准示例约束输出格式，保证描述一致性 |
| 结构化输出（JSON Mode） | 让模型输出固定字段（类型/位置/严重程度），方便模板组装 |

## 成功标尺

| 标尺 | 目标值 | 统计口径 | 数据来源 |
|------|--------|---------|---------|
| 单次报告编写时间 | <= 5分钟 | 从打开照片到提交报告的计时 | 系统前端埋点 |
| 缺陷识别准确率 | >= 90% | 正确分类数/总识别数 | 人工抽检（每月抽50份） |
| 报告退回率 | <= 8% | OA退回数/总提交数 | OA审批流统计（当前18%） |

## 项目计划

### MVP定义

第4周交付MVP：能处理**3个最常见的缺陷类型**（墙面渗水、绿化斑秃、设施损坏），覆盖**1个试点项目**。目标：证明VLM能替代人工看图写描述，准确率>=80%。

### 里程碑

| 阶段 | 时间 | 交付物 | 通过标准 |
|------|------|--------|---------|
| 第1-2周 | 6月16日-6月27日 | Top10缺陷类型梳理 + 标准描述库 + Prompt初版 | 业务方确认缺陷分类体系 |
| 第3-4周 | 6月30日-7月11日 | MVP demo：3类缺陷识别+报告生成 | 试点项目试用，准确率>=80% |
| 第5-8周 | 7月14日-8月8日 | 扩展到10类缺陷 + 报告模板对接OA | 3个项目并行试用，退回率<=12% |
| 第9-12周 | 8月11日-9月5日 | 全量测试 + 性能优化 + 结项汇报 | 准确率>=90%，退回率<=8% |

### 风险与Plan B

| 风险 | 概率 | 影响 | Plan B |
|------|------|------|--------|
| 特殊缺陷类型识别率低（如管道渗漏、结构裂缝） | 中 | 高 | 对低置信度结果自动标记"需人工复核"，不强行输出 |
| API响应慢影响一线巡检员体验 | 低 | 中 | 批量异步处理，巡检员提交照片后后台生成，完成后推送通知 |
| Claude API涨价或限额 | 低 | 中 | Prompt迁移至GPT-4o做多模型兼容，已在验证阶段测试两种模型 |

## 为什么这份好

1. **痛点有完整数据链**：不只说"效率低"，而是月均430次→25分钟/次→40%工时→18%退回率，形成完整量化链
2. **痛点有归因分析**：不只说"退回率高"，而是分析了退回原因Top3及占比
3. **方案有明确架构**：画了完整的技术流水线（拍照→VLM→结构化输出→模板→OA），不是"AI赋能"
4. **方案有对比表**：人工 vs AI辅助，逐一对比维度，差异一目了然
5. **有真实验证**：30份历史照片回测，准确率91%、可用率87%、生成耗时3.2秒/张
6. **技术选型有理由**：每项技术一句话说明解决什么问题
7. **经费逐项拆分**：用途+金额+计算方式（基于什么假设算出来的）
8. **标尺三维**：时间（效率）、准确率（质量）、退回率（业务效果），每个都有统计口径和数据来源
9. **MVP有明确边界**：第4周只做3类缺陷+1个试点，目标清晰（>=80%）
10. **风险有Plan B**：每种风险都有具体的应对方案，不是"加强测试"这种空话

## copilot引导用户时应以此为目标质量

当用户的立项书写到这个水平，Step 5的评审重点从"你这是什么"转向"怎么做得更好"。
